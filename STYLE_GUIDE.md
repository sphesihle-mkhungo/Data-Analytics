# Agricultural Data Science Toolkit
# Style Guide

Version: 1.0

---

# Purpose

This style guide defines the standards used throughout the Agricultural Data Science Toolkit.

The aim is to ensure that every module follows a consistent structure, writing style, coding standard, and educational philosophy.

---

# Vision

The Agricultural Data Science Toolkit is an open-source educational resource designed to help students, researchers, and professionals develop practical skills in agricultural data science, statistics, programming, GIS, and machine learning.

The emphasis is on:

- Scientific accuracy
- Reproducibility
- Practical application
- Clear communication
- Open science

---

# Writing Standards

- Write in clear, professional English.
- Use British English spelling.
- Explain concepts before introducing code.
- Avoid unnecessary jargon.
- Assume the reader has basic statistical knowledge but is new to programming.
- Use examples from agriculture, ecology, environmental science, and biological research whenever possible.

---

# Documentation Standards

Every module should include:

- Overview
- Learning objectives
- Key concepts
- Practical examples
- Code examples
- Exercises
- References

---

# Coding Standards

## General

- Use meaningful variable names.
- Keep code modular.
- Write reusable functions.
- Avoid duplicated code.
- Comment important sections.
- Ensure every script runs independently.

---

## R Standards

- Use snake_case object names.
- Prefer tidyverse where appropriate.
- Load packages at the beginning.
- Include package installation notes where required.
- Add script headers.

Example:

Author

Purpose

Input

Output

Date

---

## Python Standards

- Follow PEP 8.
- Use descriptive function names.
- Use pandas for tabular data.
- Use pathlib for file paths where appropriate.
- Write docstrings for functions.

---

# Figure Standards

Figures should:

- Have informative titles.
- Label all axes.
- Include units.
- Use readable fonts.
- Be publication quality.

---

# Dataset Standards

Every dataset should include:

- Source
- Description
- Variable definitions
- Units
- Missing value information
- Citation

---

# Case Studies

Case studies should:

- Be based on real agricultural or ecological problems.
- Explain the research question.
- Describe the dataset.
- Demonstrate the workflow.
- Interpret the results.
- Discuss limitations.

---

# Exercises

Exercises should progress from:

Beginner

↓

Intermediate

↓

Advanced

Each exercise should have a complete worked solution.

---

# References

References should:

- Prefer peer-reviewed literature.
- Include textbooks where appropriate.
- Cite software documentation.
- Follow APA 7th Edition.

---

# Version Control

Every major update should:

- Update the CHANGELOG.
- Update the ROADMAP if required.
- Increase the repository version when appropriate.

---

# Educational Philosophy

This toolkit is not simply a collection of scripts.

It is intended to teach:

- Why analyses are performed.
- When methods should be used.
- How analyses are implemented.
- How results should be interpreted.
- How findings should be communicated.

The ultimate goal is to promote reproducible, high-quality agricultural data science.
